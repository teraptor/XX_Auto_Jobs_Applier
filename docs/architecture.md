## Обзор архитектуры

XX Auto Jobs Applier построен на модульной архитектуре с четким разделением ответственности между компонентами. Приложение следует принципам SOLID и использует паттерн Facade для упрощения взаимодействия между модулями.

### Ключевые принципы проектирования

1. **Модульность** - каждый компонент отвечает за свою область
2. **Разделение ответственности** - бизнес-логика отделена от конфигурации
3. **Расширяемость** - легко добавить новые LLM провайдеры или функции
4. **Безопасность** - приватные данные изолированы от кода

## Основные компоненты

### 1. Entry Point (main.py)

**Ответственность:**
- Инициализация приложения
- Валидация конфигурации
- Запуск основного процесса
- Обработка ошибок верхнего уровня

**Ключевые классы:**
- `ConfigValidator` - проверка корректности настроек
- `FileManager` - управление файловой структурой
- `create_and_run_bot()` - создание и запуск бота

**Поток выполнения:**
```
1. Проверка наличия data_folder и необходимых файлов
2. Валидация secrets.yaml через Pydantic модели
3. Валидация search_config.yaml через Pydantic модели
4. Создание компонентов бота
5. Запуск процесса поиска и откликов
6. Логирование результатов
```

### 2. Job Manager (src/job_manager/)

Центральный модуль для работы с вакансиями на hh.ru.

#### api.py - HeadHunterAPI
**Назначение:** Взаимодействие с API hh.ru

**Основные методы:**
- `get_vacancies()` - поиск вакансий
- `get_vacancy_details()` - подробная информация о вакансии
- `apply_to_vacancy()` - отклик на вакансию
- `get_resume()` - получение данных резюме
- `refresh_tokens()` - обновление токенов доступа
- `raise_resume()` - подъем резюме в поиске

**Используемые API endpoints:**
- `/vacancies` - поиск вакансий
- `/vacancies/{id}` - детали вакансии
- `/negotiations` - отправка откликов
- `/resumes` - работа с резюме
- `/token` - обновление токенов

#### authenticator.py - Authenticator
**Назначение:** Авторизация на сайте hh.ru через Selenium

**Функции:**
- Автоматический вход на сайт
- Обработка CAPTCHA (с помощью Telegram)
- Сохранение сессии в профиле Chrome
- Повторное использование сессии

**Особенности:**
- Использует Selenium WebDriver
- Сохраняет профиль браузера в `chrome_profile/`
- Интеграция с Telegram для решения капчи

#### bot_facade.py - BotFacade
**Назначение:** Паттерн Facade для координации всех компонентов

**Функции:**
- Координация ResumeScraper, SearchCustomizer, JobApplier
- Управление жизненным циклом процесса откликов
- Агрегация результатов

**Методы:**
- `set_parameters()` - установка параметров поиска
- `set_resume()` - загрузка данных резюме
- `set_search_parameters()` - настройка фильтров поиска
- `set_gpt_answerer()` - подключение LLM
- `start_apply()` - запуск процесса откликов

#### job_applier.py - JobApplier
**Назначение:** Основная логика поиска и откликов на вакансии

**Ключевые методы:**
```python
def start_applying():
    """Главный цикл обработки вакансий"""
    while success_applies < max_applies:
        vacancies = search_vacancies(page)
        for vacancy in vacancies:
            result = send_response(vacancy)
            
def send_response(vacancy):
    """Обработка одной вакансии"""
    1. Проверка на дубликаты
    2. Оценка соответствия (LLM)
    3. Формирование отклика
    4. Ответы на вопросы (LLM)
    5. Генерация сопроводительного письма (LLM)
    6. Отправка отклика
```

**Режимы работы:**
- `MONKEY_MODE` - отклик на все вакансии подряд
- Нормальный режим - фильтрация через LLM
- `RESUME_MODE` - только генерация резюме
- `COVER_LETTER_MODE` - только генерация писем
- `SKILL_STAT_MODE` - сбор статистики навыков

**Управление лимитами:**
- `max_applies_num` - лимит на запуск
- `max_total_applies_num` - общий лимит
- `APPLY_ONCE_AT_COMPANY` - один отклик на компанию
- Таймауты между откликами

#### resume_scraper.py - ResumeScraper
**Назначение:** Сбор и структурирование данных резюме

**Функции:**
- Получение резюме через API
- Парсинг структуры резюме
- Извлечение навыков, опыта, образования
- Сохранение в `data_folder/output/resume.yaml`

**Извлекаемые данные:**
- Личная информация (анонимизируется для LLM)
- Опыт работы (компании, должности, обязанности)
- Навыки и технологии
- Образование
- Языки
- Сертификаты

#### search_customizer.py - SearchCustomizer
**Назначение:** Настройка параметров поиска на hh.ru

**Функции:**
- Формирование запроса поиска
- Применение фильтров
- Обработка географических параметров
- Настройка сортировки

**Поддерживаемые параметры:**
- Ключевые слова и исключения
- География (регионы, метро)
- Зарплата и валюта
- Опыт работы
- График и тип занятости
- Специализация и отрасль

```python
class Secrets(BaseModel):

class SearchConfig(BaseModel):
    """Валидация search_config.yaml"""
    job_title: str
    user_id: str
    max_applies_num: int = 200
    keywords: Optional[str]
    salary: Optional[int]
    # ... множество других полей
    
    @validator('experience')
    def only_one_true(cls, v):
        """Только одно значение может быть True"""
        true_count = sum(v.values())
        if true_count != 1:
            raise ValueError("Только один опыт может быть выбран")
        return v
```

```
┌─────────────────────────────────────────────────────────────┐
│ 1. ИНИЦИАЛИЗАЦИЯ                                            │
└─────────────────────────────────────────────────────────────┘

   │
   ├─→ Создание компонентов:
   │   ├─→ HeadHunterAPI (api.py)
   │   ├─→ GPTAnswerer (llm_manager.py)
   │   ├─→ ResumeScraper (resume_scraper.py)
   │   ├─→ SearchCustomizer (search_customizer.py)
   │   ├─→ JobApplier (job_applier.py)
   │   └─→ BotFacade (bot_facade.py)
   │
   ▼

┌─────────────────────────────────────────────────────────────┐
│ 2. ПОЛУЧЕНИЕ ДАННЫХ РЕЗЮМЕ                                  │
└─────────────────────────────────────────────────────────────┘
   │
   ├─→ ResumeScraper.get_resume()
   │   ├─→ API запрос к /resumes
   │   ├─→ Парсинг структуры
   │   └─→ Сохранение в resume.yaml
   │
   ▼

┌─────────────────────────────────────────────────────────────┐
│ 3. НАСТРОЙКА ПОИСКА                                         │
└─────────────────────────────────────────────────────────────┘
   │
   ├─→ SearchCustomizer.set_search_parameters()
   │   ├─→ Формирование фильтров
   │   └─→ Подготовка запроса
   │
   ▼

┌─────────────────────────────────────────────────────────────┐
│ 4. ПОИСК ВАКАНСИЙ                                           │
└─────────────────────────────────────────────────────────────┘
   │
   ├─→ JobApplier.search_vacancies(page)
   │   ├─→ API запрос к /vacancies
   │   └─→ Получение списка вакансий
   │
   ▼

┌─────────────────────────────────────────────────────────────┐
│ 5. ОБРАБОТКА КАЖДОЙ ВАКАНСИИ (цикл)                        │
└─────────────────────────────────────────────────────────────┘
   │
   ├─→ Проверка на дубликаты
   │   └─→ Поиск в success.yaml/skipped.yaml
   │
   ├─→ Проверка черного списка
   │   └─→ job_blacklist из search_config
   │
   ├─→ Получение деталей вакансии
   │   └─→ API /vacancies/{id}
   │
   ├─→ ОЦЕНКА СООТВЕТСТВИЯ (если не MONKEY_MODE)
   │   ├─→ GPTAnswerer.job_is_interesting()
   │   │   ├─→ Отправка промпта в LLM
   │   │   ├─→ Анонимизация данных
   │   │   └─→ Получение оценки 1-100
   │   │
   │   └─→ Если оценка < JOB_IS_INTERESTING_THRESH:
   │       └─→ Сохранить в skipped.yaml
   │
   ├─→ ОТВЕТЫ НА ВОПРОСЫ
   │   ├─→ Для каждого вопроса работодателя:
   │   │   ├─→ Проверка кэша (answers.yaml)
   │   │   └─→ Если нет в кэше:
   │   │       ├─→ GPTAnswerer.answer_question()
   │   │       └─→ Сохранить в answers.yaml
   │   │
   │   └─→ Формирование списка ответов
   │
   ├─→ ГЕНЕРАЦИЯ СОПРОВОДИТЕЛЬНОГО ПИСЬМА
   │   ├─→ Если cover_letter заполнен:
   │   │   └─→ Использовать готовое письмо
   │   │
   │   └─→ Иначе:
   │       ├─→ GPTAnswerer.generate_cover_letter()
   │       └─→ Сохранить в cover_letters.txt
   │
```

## Обработка ошибок

### Стратегия обработки

```
┌─────────────────────────────────────────────┐
│         Уровни обработки ошибок             │
└─────────────────────────────────────────────┘

1. API Level (api.py)
   ├─→ Retry механизм (3 попытки)
   ├─→ Обработка HTTP ошибок
   ├─→ Автообновление токенов
   └─→ Логирование запросов/ответов

2. LLM Level (llm_manager.py)
   ├─→ Fallback на другие модели
   ├─→ Обработка rate limits
   ├─→ Повторные попытки с экспоненциальной задержкой
   └─→ Логирование стоимости

3. Application Level (job_applier.py)
   ├─→ Счетчик последовательных ошибок
   ├─→ Сохранение неудачных вакансий в failed.yaml
   ├─→ Продолжение работы после ошибки
   └─→ Критическое завершение при MAX_APPLIES_NUM ошибок

4. Main Level (main.py)
   ├─→ ConfigError → вывод сообщения, завершение
   ├─→ FileNotFoundError → вывод подсказки, завершение
   ├─→ RuntimeError → полный traceback, уведомление в Telegram
   └─→ Exception → логирование, попытка восстановления

5. Telegram Notifications
   ├─→ Критические ошибки → топик "Errors"
   ├─→ CAPTCHA → топик "Captcha" с интерактивным решением
   └─→ Итоговый отчет → топик "Reports"
```
