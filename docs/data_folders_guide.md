## Назначение папок

### data_folder_example - Эталонные примеры
Папка `data_folder_example` содержит **примеры конфигурационных файлов** с пояснениями и вымышленными данными. Это справочная папка, которая помогает понять правильный формат и структуру настроек.

**Основные функции:**
- 📖 Обучающие примеры для новых пользователей
- 🔍 Справочник по структуре конфигурационных файлов
- ✅ Шаблоны для создания собственных настроек
- 📝 Документация допустимых значений полей

### data_folder - Рабочие данные
Папка `data_folder` содержит **реальные конфигурационные файлы и результаты работы** приложения. Это основная рабочая директория приложения.

**Основные функции:**
- 🔐 Хранение приватных настроек и секретов
- ⚙️ Конфигурация параметров поиска вакансий
- 📊 Сохранение результатов работы приложения
- 🗃️ Кэширование данных для оптимизации работы

## data_folder_example - Эталонные примеры

### Структура
```
data_folder_example/
├── secrets/
│   └── secrets.yaml          # Пример файла с секретными ключами
└── search_config/
    └── search_config.yaml    # Пример файла настроек поиска
```

### Назначение файлов

#### secrets/secrets.yaml
Пример файла с приватными данными и API ключами:

```yaml
access_token: gdas$X12                    # Токен доступа к hh API
refresh_token: dfgsff7                    # Токен обновления доступа к hh API

hh_login: your_hh_login                   # Логин на hh.ru
hh_password: your_hh_password             # Пароль на hh.ru

llm_api_key: sk-proj-...                  # API ключ для LLM (OpenAI/Gemini)
llm_proxy:                                # Список прокси для LLM API
  - http://user:pass@143.121.247.171:62522

tg_token: 7975384203:AAGgx0f...           # Токен Telegram бота
tg_api_id: 735738                         # Telegram API ID
tg_api_hash: ff29041dgfaa...              # Telegram API Hash
```

**⚠️ Важно:** Данные в этом файле - вымышленные примеры для демонстрации формата!

#### search_config/search_config.yaml
Пример файла с настройками поиска вакансий (122 строки):

**Основные разделы:**
1. **Базовые параметры поиска:**
   - `job_title` - должность (обязательное поле)
   - `keywords` - ключевые слова для поиска
   - `search_field` - где искать (название, компания, описание)
   - `words_to_exclude` - исключаемые слова

2. **Фильтры вакансий:**
   - `professional_role` - специализация
   - `industry` - отрасль компании
   - `area` - регионы поиска
   - `metro` - станции метро
   - `salary` - уровень дохода
   - `currency` - валюта зарплаты

3. **Требования к кандидату:**
   - `experience` - требуемый опыт работы
   - `education` - требуемое образование

4. **Условия работы:**
   - `employment` - тип занятости (полная, частичная)
   - `schedule` - график работы (полный день, удаленка)
   - `part_time` - параметры подработки

5. **Дополнительные фильтры:**
   - `vacancy_label` - особые параметры (адрес, доступность)
   - `order_by` - сортировка результатов
   - `period` - период публикации вакансий

6. **Управление откликами:**
   - `job_blacklist` - список игнорируемых компаний
   - `cover_letter` - готовое сопроводительное письмо
   - `apply_once_at_company` - ограничение откликов на компанию
   - `skip_companies_with_test` - пропуск вакансий с тестовыми заданиями

7. **Лимиты:**
   - `max_applies_num` - максимум откликов за запуск (по умолчанию: 200)
   - `max_total_applies_num` - общий лимит откликов

8. **Идентификация:**
   - `user_id` - ID пользователя на hh.ru (обязательное поле)

**📌 Все поля подробно закомментированы в файле примера!**

## data_folder - Рабочие данные

### Структура
```
data_folder/
├── secrets/
│   └── secrets.yaml          # ВАШИ реальные секреты
├── search_config/
│   └── search_config.yaml    # ВАШИ настройки поиска
└── output/                   # Результаты работы приложения
    ├── answers.yaml          # Кэш ответов LLM на вопросы
    ├── failed.yaml           # Неудачные отклики (ошибки)
    ├── skipped.yaml          # Пропущенные вакансии (+ причины)
    ├── success.yaml          # Успешные отклики
    ├── llm_api_calls.yaml    # Лог всех запросов к LLM
    ├── resume.yaml           # Информация о резюме
    ├── cover_letters.txt     # Сгенерированные письма
    ├── search_config_tmp.yaml # Временный файл конфигурации
    └── last_run.yaml         # Данные о последнем запуске
```

### Назначение подпапок

#### secrets/
Содержит приватные данные:
- Токены доступа к API HeadHunter
- Логин и пароль на hh.ru
- API ключи для LLM (OpenAI, Gemini, Claude)
- Настройки прокси
- Токены Telegram бота

**🔒 КРИТИЧЕСКИ ВАЖНО:**
- Никогда не делитесь содержимым этой папки
- Не добавляйте в систему контроля версий (Git)
- Используйте команду: `git update-index --assume-unchanged data_folder/secrets/secrets.yaml`

#### search_config/
Содержит настройки поиска вакансий:
- Параметры фильтрации вакансий
- Географические настройки
- Требования к зарплате и опыту
- Черные списки компаний
- Шаблоны сопроводительных писем

**⚙️ Эти файлы можно редактировать между запусками для изменения поведения бота**

#### output/
Автоматически создаваемая папка с результатами работы.

## Файлы конфигурации

### secrets.yaml - Секретные данные

**Обязательные поля:**
```yaml
access_token: "ваш_токен"      # Получается через hh.ru API
refresh_token: "ваш_токен"     # Обновляется автоматически
hh_login: "логин"              # Для авторизации на сайте
hh_password: "пароль"          # Для авторизации на сайте
llm_api_key: "ключ_api"        # Для работы с AI
```

**Опциональные поля:**
```yaml
llm_proxy:                     # Прокси для обхода ограничений
  - "http://user:pass@IP:port"
tg_token: "токен"              # Для уведомлений в Telegram
tg_api_id: "id"                # Для чтения сообщений (капча)
tg_api_hash: "hash"            # Для чтения сообщений (капча)
```

### search_config.yaml - Настройки поиска

**Обязательные поля:**
- `job_title` - должность (ДОЛЖНА совпадать с названием резюме на hh.ru!)
- `user_id` - ваш ID на hh.ru
- `max_applies_num` - лимит откликов за запуск

**Важные опциональные поля:**
- `cover_letter` - если заполнено, используется для всех вакансий
- `job_blacklist` - компании, которые нужно игнорировать
- `experience` - ТОЛЬКО ОДНО значение должно быть `true`
- `currency` - ТОЛЬКО ОДНО значение должно быть `true`
- `order_by` - ТОЛЬКО ОДНО значение должно быть `true`
- `period` - ТОЛЬКО ОДНО значение должно быть `true`

## Выходные данные

### answers.yaml
**Назначение:** Кэширование ответов LLM на вопросы работодателей

**Зачем это нужно:**
- Избегание повторных запросов к LLM (экономия денег)
- Консистентность ответов на одинаковые вопросы
- Ускорение обработки вакансий

**Формат:**
```yaml
- question: "Опишите ваш опыт работы с Python"
  answer: "У меня 5 лет опыта разработки на Python..."
  question_type: "work_experience"
```

### success.yaml
**Назначение:** Лог успешных откликов

**Формат:**
```yaml
- vacancy_url: "https://hh.ru/vacancy/123456"
  company_name: "Компания ABC"
  position: "Python Developer"
  timestamp: "2025-10-22 14:30:15"
  cover_letter_used: true
```

### failed.yaml
**Назначение:** Вакансии с программными ошибками

**Формат:**
```yaml
- vacancy_url: "https://hh.ru/vacancy/789012"
  error_message: "Timeout при отправке отклика"
  timestamp: "2025-10-22 14:35:20"
```

### skipped.yaml
**Назначение:** Пропущенные вакансии (не по причине ошибок)

**Причины пропуска:**
- Низкая оценка соответствия от LLM
- Компания в черном списке
- Уже откликались ранее
- Достигнут лимит откликов в компанию

### llm_api_calls.yaml
**Назначение:** Полный лог взаимодействия с LLM

**Что содержит:**
- Все промпты отправленные в LLM
- Полученные ответы
- Стоимость каждого запроса
- Количество токенов

**Использование:** Отладка, анализ расходов, оптимизация промптов

### resume.yaml
**Назначение:** Извлеченная информация о резюме пользователя

**Содержимое:**
- Опыт работы
- Навыки и технологии
- Образование
- Контактная информация (анонимизированная для LLM)

### cover_letters.txt
**Назначение:** Текстовый лог всех сгенерированных сопроводительных писем

**Использование:**
- Проверка качества генерации
- Поиск и исправление "кринжа"
- Анализ стиля написания

## Безопасность данных

### Что хранится локально
✅ **ВСЕ данные хранятся только на вашем компьютере:**
- Секретные токены и пароли
- Настройки поиска
- История откликов
- Логи работы приложения

### Что отправляется в LLM
⚠️ **Анонимизированная информация:**
- Текст вакансий
- Резюме с замененными личными данными
- Вопросы работодателей (без контекста компании)

**Механизм анонимизации:**
Ваши реальные данные (ФИО, телефон, email) автоматически заменяются на вымышленные перед отправкой в LLM. Настройки пустышек находятся в `src/constants.py`:
- `DUMMY_PERSONAL_INFO_MALE` - для мужчин
- `DUMMY_PERSONAL_INFO_FEMALE` - для женщин

### Рекомендации по безопасности

1. **Для secrets.yaml:**
   ```bash
   # Исключить из Git
   git update-index --assume-unchanged data_folder/secrets/secrets.yaml
   
   # Или удалить из отслеживаемых
   git rm --cached data_folder/secrets/secrets.yaml
   ```

2. **Права доступа:**
   ```bash
   # Ограничить доступ к папке secrets (Linux/Mac)
   chmod 700 data_folder/secrets
   chmod 600 data_folder/secrets/secrets.yaml
   ```

3. **Резервное копирование:**
   - Храните копии secrets.yaml в безопасном месте
   - Используйте менеджеры паролей для API ключей
   - Не храните токены в облаке без шифрования

## Быстрый старт

### 1. Первоначальная настройка

```bash
# Скопируйте примеры
cp data_folder_example/secrets/secrets.yaml data_folder/secrets/
cp data_folder_example/search_config/search_config.yaml data_folder/search_config/

# Отредактируйте файлы, заменив примеры на реальные данные
nano data_folder/secrets/secrets.yaml
nano data_folder/search_config/search_config.yaml
```

### 2. Минимально необходимые изменения

**В secrets.yaml:**
- Вставьте реальные `access_token` и `refresh_token` (см. README.md)
- Вставьте логин и пароль от hh.ru
- Добавьте `llm_api_key` для выбранной LLM

**В search_config.yaml:**
- Измените `job_title` на название вашего резюме
- Укажите ваш `user_id` с hh.ru
- Настройте фильтры поиска под себя

### 3. Запуск

```bash
python main.py
```

Приложение автоматически создаст папку `output` и начнет записывать результаты.

## Частые вопросы (FAQ)

**Q: Могу ли я удалить папку data_folder_example?**
A: Да, после настройки она не используется приложением. Но лучше оставить для справки.

**Q: Что делать, если забыл какие значения можно использовать?**
A: Смотрите в `data_folder_example/search_config/search_config.yaml` - там все значения закомментированы.

**Q: Можно ли очистить папку output?**
A: Да, но при удалении `answers.yaml` LLM будет заново отвечать на все вопросы (дороже).

**Q: Где найти user_id на hh.ru?**
A: В URL вашего резюме: `https://hh.ru/applicant/resumes/view?resume=USER_ID`

**Q: Обязательно ли заполнять все поля в search_config.yaml?**
A: Нет, только поля помеченные как "обязательное поле" в комментариях.

**Q: Что делать если токены hh API истекли?**
A: Приложение автоматически обновит `refresh_token`. Если не работает - повторите процесс получения токенов из README.

**Q: Можно ли использовать несколько профилей поиска?**
A: Да, создайте копии search_config.yaml и указывайте нужный при запуске (требует модификации кода).
