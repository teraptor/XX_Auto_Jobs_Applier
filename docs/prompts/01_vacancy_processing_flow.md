# Полный цикл обработки вакансии с использованием промптов

## Обзор

Данный документ детально описывает, как промпты LLM используются в процессе обработки одной вакансии от начала до момента отправки отклика.

---

## Детальное описание каждого шага

### Шаг 1: Проверка дубликатов

**Цель**: Избежать повторных откликов на одну и ту же вакансию

**Проверяемые файлы**:
- `success.yaml` - успешно обработанные вакансии
- `skipped.yaml` - пропущенные вакансии
- `failed.yaml` - вакансии с ошибками

**Структура записи**:
```yaml
company_name:
  - vacancy_title: "Python Developer"
    url: "https://hh.ru/vacancy/12345"
    date: "2025-10-22"
    reason: "Successfully applied"
```

**Логика**:
```
if vacancy_id in success.yaml:
    return "Skip", "Уже откликались на эту вакансию"
if company_name in search_config.job_blacklist:
    return "Skip", "Компания в черном списке"
```

**LLM вызовы**: ❌ Нет

### Шаг 2: Получение деталей вакансии

**API запрос**:
```
GET https://api.hh.ru/vacancies/{vacancy_id}
Headers:
  Authorization: Bearer {access_token}
```

**Ответ** (сокращенно):
```json
{
  "id": "12345",
  "name": "Python Developer",
  "description": "Полное HTML описание вакансии...",
  "key_skills": [{"name": "Python"}, {"name": "Django"}],
  "employer": {
    "name": "Company X",
    "url": "https://company.com"
  },
  "salary": {
    "from": 150000,
    "to": 250000,
    "currency": "RUR"
  },
  "has_test": false,
  "response_letter_required": true
}
```

**Обработка**:
- Извлечь description (HTML → plain text)
- Извлечь key_skills
- Сохранить employer info
- Проверить has_test

**LLM вызовы**: ❌ Нет

### Шаг 3: Суммаризация описания вакансии

**Зачем**: Сократить количество токенов для последующих LLM вызовов

**Входные данные**:
- Полное описание вакансии: 2000-8000 токенов
- Обязанности, требования, условия

**Промпт**: `summarize_prompt_template`

**Выходные данные**:
- Структурированное резюме: 500-1500 токенов
- Разделы:
  1. Краткое описание вакансии (2 предложения)
  2. Обязанности (список)
  3. Hard skills (список)
  4. Soft skills (список)
  5. Требования к образованию и сертификатам
  6. Профессиональный опыт
  7. Эволюция должности

**Пример output**:
```
## Краткое описание вакансии
Company X ищет Python разработчика для работы над внутренними сервисами. 
Компания занимается разработкой финтех решений.

## Обязанности
- Разработка и поддержка микросервисов на Python
- Оптимизация производительности приложений
- Code review и менторинг junior разработчиков

## Hard skills
- Python (3+ года опыта)
- Django или FastAPI
- PostgreSQL
- Docker
- Git

## Soft skills
- Командная работа
- Самостоятельность
- Внимание к деталям

## Требования к образованию
- Высшее техническое образование (приветствуется)

## Профессиональный опыт
- 3+ года опыта разработки на Python
- Опыт с REST API
- Опыт с базами данных

## Эволюция должности
В будущем возможен переход в роль Tech Lead или Architect
```

**Токены**:
- Input: ~3000 токенов
- Output: ~800 токенов

**Стоимость** (gemini-2.0-flash):
- Input: 3000 × $0.0000001 = $0.0003
- Output: 800 × $0.0000004 = $0.000032
- **Итого**: $0.000332

**Кэширование**: ❌ Нет (каждая вакансия уникальна)

### Шаг 4: Проверка MONKEY_MODE

**Что это**: Режим "обезьяны" - откликаться на ВСЕ вакансии без оценки

**Настройка**: `src/app_config.py`
```python
MONKEY_MODE = False  # По умолчанию отключен
```

**Логика**:
```
if MONKEY_MODE == True:
    job_is_interesting = True  # Принудительно считаем интересной
    # Пропускаем LLM вызов job_is_interesting
    # Сразу переход к применению
else:
    # Вызвать LLM для оценки (Шаг 5)
```

**Применение**:
- Тестирование системы
- Агрессивный поиск работы (откликнуться на максимум вакансий)
- Сбор статистики

**Предупреждение**: Может привести к нерелевантным откликам!

### Шаг 5: Оценка соответствия вакансии (LLM)

**Промпт**: `job_is_interesting`

**Входные данные**:
```
resume: JSON структура резюме (2000-4000 токенов)
  - personal_information
  - experience_details
  - education_details
  - skills
  - languages
  - certifications

job_description: Суммари из Шага 3 (500-1500 токенов)

search_parameters: Параметры поиска из config (200-500 токенов)
  - job_title
  - keywords
  - salary expectations
  - work schedule
  - employment type
```

**Промпт структура**:
```
You are an expert in recruitment.
Evaluate whether the provided resume meets the requirements...

##Job Description##
{суммари вакансии}

##Resume##
{данные резюме}

##Search Parameters##
{параметры поиска}

##Additional Rules##
- Identify key requirements (mandatory vs desirable)
- Compare qualifications to requirements
- Assign score 1-100
- Subtract 20 points if skill level mismatch
- Subtract 10 points if overqualified
- Add 10 points if aligns with interests
- Subtract 20 points per search parameter mismatch

Output format:
Score: [1-100]
Reasoning: [explanation]
```

**Пример output**:
```
Score: 75
Reasoning: Candidate has 4 years of Python experience (meets 3+ requirement). 
Strong match in Django and PostgreSQL. Missing Docker experience but this is 
not a strict requirement. Salary expectations align with offer. Overall good fit.
```

**Обработка ответа**:
```python
# Парсинг
score = re.search(r"Score: (\d+)", output).group(1)
reasoning = re.search(r"Reasoning: (.+)", output).group(1)

# Валидация
if int(score) < JOB_IS_INTERESTING_THRESH:  # default: 60
    logger.info(f"Вакансия не интересна: {reasoning}")
    return False  # SKIP вакансию
else:
    logger.info(f"Вакансия интересна (score: {score})")
    return True   # Продолжить обработку
```

**Токены**:
- Input: ~3500 токенов
- Output: ~200 токенов

**Стоимость** (gemini-2.0-flash):
- Input: 3500 × $0.0000001 = $0.00035
- Output: 200 × $0.0000004 = $0.00008
- **Итого**: $0.00043

**Кэширование**: ❌ Нет

**Возможные ответы**:

**4. Другие ошибки**:
→ Сохранить в failed.yaml, продолжить со следующей вакансией

### Шаг 8: Обработка вопросов (Selenium + LLM)

**Когда**: Только если API вернул `test_required`

**Процесс**:

**8.1. Запуск Selenium**:
```
driver = init_driver()  # Chrome WebDriver
authenticator.start()   # Вход на сайт (если нужно)
```

**8.2. Открытие страницы отклика**:
```
URL: https://hh.ru/applicant/vacancy_response?vacancyId={id}
driver.get(URL)
pause(2-3 sec)  # Загрузка страницы
```

**8.3. Поиск вопросов**:
```
questions = driver.find_elements("xpath", "//*[@data-qa='task-body']")
```

**8.4. Для каждого вопроса**:

**Определение типа**:
```python
# Radio button (один вариант)
if question.find_elements("xpath", ".//input[@type='radio']"):
    question_type = "radio"
    
# Checkbox (множественный выбор)
elif question.find_elements("xpath", ".//input[@type='checkbox']"):
    question_type = "checkbox"
    
# Text input (текстовый ответ)
elif question.find_elements("xpath", ".//textarea"):
    question_type = "text"
```

**Проверка кэша**:
```python
# Нормализация текста вопроса
question_text = question.text.strip()

# Поиск в кэше
cached_answer = answers_cache.get(question_text)

if cached_answer:
    # Использовать готовый ответ
    answer = cached_answer
    logger.info(f"Найден ответ в кэше: {answer}")
    # Без LLM вызова
else:
    # Вызвать LLM
    answer = llm.answer_question(question_text, question_type)
    # Сохранить в кэш
    answers_cache[question_text] = answer
```

**LLM вызов (если нет в кэше)**:

**Для Radio**:
```
ПРОМПТ: options_template
INPUT:
  - resume: {резюме}
  - question: "How many years of Python experience?"
  - options: ["1-2", "3-5", "6-10", "10+", "No info"]
OUTPUT:
  - "6-10"
```

**Для Checkbox**:
```
ПРОМПТ: many_options_template
INPUT:
  - resume: {резюме}
  - question: "Which technologies do you know?"
  - options: ["Python", "Java", "C++", "Go", "Rust"]
OUTPUT:
  - "Python; Go"
```

**Для Text**:
```
ПРОМПТ: text_question_answer_template
INPUT:
  - resume: {резюме}
  - question: "Why are you interested in this position?"
  - sex: "мужской"
  - current_date: "2025-10-22"
OUTPUT:
  - "Меня привлекает возможность работы с современными технологиями..."
```

**Заполнение формы**:
```python
# Radio: Выбрать вариант
if question_type == "radio":
    radio_button = question.find_element("xpath", f".//label[contains(text(), '{answer}')]")
    radio_button.click()

# Checkbox: Отметить все подходящие
elif question_type == "checkbox":
    for answer_option in answer.split(";"):
        checkbox = question.find_element("xpath", f".//label[contains(text(), '{answer_option.strip()}')]")
        checkbox.click()

# Text: Ввести текст
elif question_type == "text":
    textarea = question.find_element("xpath", ".//textarea")
    textarea.send_keys(answer)
```

**Среднее количество вопросов**: 0-5 на вакансию
**Время обработки**: 2-3 секунды на вопрос
**LLM вызовы**: 0-5 (зависит от кэша и количества вопросов)

### Шаг 9: Генерация сопроводительного письма (LLM)

## Оптимизации

### 1. Пропуск суммаризации (опционально)

**Идея**: Использовать полное описание вместо суммари

**Плюсы**:
- Экономия 1 LLM вызова (~$0.0003)

**Минусы**:
- Увеличение токенов в последующих вызовах
- Общая стоимость может вырасти

**Рекомендация**: Оставить суммаризацию

### 2. Использование фиксированного письма

**Настройка**: В `search_config.yaml`:
```yaml
cover_letter: |
  Здравствуйте!
  
  Прошу рассмотреть моё резюме на открытую вакансию.
  
  С уважением,
  Иван Сидоров
```

**Плюсы**:
- Экономия 1 LLM вызова (~$0.0005)
- Быстрее обработка

**Минусы**:
- Не персонализировано под вакансию
- Ниже шанс успеха

### 3. Кэширование ответов на вопросы

**Реализовано**: ✅ Да

**Эффект**:
- После 50-100 вакансий кэш покрывает ~70% вопросов
- Экономия ~$0.0003-0.0007 на вакансию
- Ускорение обработки на 5-10 секунд
