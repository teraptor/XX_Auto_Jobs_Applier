## 🎯 Ключевые концепции

### 1. Типы промптов

**Основные (используются всегда)**:
- `job_is_interesting` - Оценка соответствия вакансии
- `summarize_prompt_template` - Суммаризация описания
- `coverletter_template` - Генерация письма

**Вопросы работодателя (опционально)**:
- `text_question_answer_template` - Текстовые ответы
- `options_template` - Выбор одного варианта
- `many_options_template` - Выбор нескольких вариантов

**Резюме билдер (отдельный модуль)**:
- 7 промптов для генерации секций резюме

---

### 2. Экономика LLM

**Стоимость обработки одной вакансии**:
- Минимум: $0.00075 (только оценка, отсев)
- Обычно: $0.0015-0.0025 (с письмом и вопросами)
- Максимум: $0.004-0.006 (много вопросов)

**Ключевые оптимизации**:
- ✅ Кэширование ответов на вопросы (30-40% экономия)
- ✅ Использование gemini-2.0-flash (в 2х дешевле gpt-4o-mini)
- 🔧 Dual model strategy (40-50% экономия)
- 🔧 Batch processing (20-30% экономия)

---

### 3. Анонимизация данных

**Зачем**: LLM не должна видеть реальные персональные данные

**Что анонимизируется**:
- ФИО → Алексей Петров / Екатерина Иванова
- Телефон → +7 (999) 000-00-00
- Email → alex.petrov@example.com
- Telegram → @alex_example

**Когда деанонимизация**: Только перед отправкой отклика через API

---

### 4. Кэширование

**Что кэшируется**:
- ✅ Ответы на вопросы (`answers.yaml`)
- 🔧 Суммаризация вакансий (рекомендуется реализовать)
- 🔧 Оценка пар резюме-вакансия (опционально)

**Эффект**: 30-40% экономия на LLM вызовах

## 🔧 Рекомендации для Go реализации

### Архитектурные решения

**1. Модуль LLM Client**:
```
type LLMClient interface {
    Invoke(prompt string, data map[string]interface{}) (string, error)
    InvokeWithCache(cacheKey string, prompt string, data map[string]interface{}) (string, error)
}
```

**2. Кэш интерфейс**:
```
type PromptCache interface {
    Get(key string) (string, bool)
    Set(key string, value string) error
    Clear() error
}
```

**3. Промпт менеджер**:
```
type PromptManager struct {
    client LLMClient
    cache  PromptCache
    logger Logger
}
```

## 🐛 Часто встречающиеся проблемы

### Проблема 1: Высокая стоимость

**Симптомы**: Стоимость > $0.005 на вакансию

**Решения**:
- Проверить, включено ли кэширование
- Убедиться, что используется gemini-2.0-flash
- Проверить размер промптов (может быть слишком много данных)
- Внедрить dual model strategy

---

### Проблема 2: Низкий cache hit rate

**Симптомы**: < 30% попаданий в кэш после 1000 вакансий

**Решения**:
- Нормализовать текст вопросов (trim, lowercase)
- Проверить TTL кэша (не слишком ли короткий)
- Убедиться, что кэш персистентный

---

### Проблема 3: Частые ошибки LLM

**Симптомы**: > 5% неудачных вызовов

**Решения**:
- Проверить API ключ
- Убедиться в обработке rate limits
- Добавить retry logic
- Проверить размер промптов (может превышать лимиты)
